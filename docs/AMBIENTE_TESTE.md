# Ambiente de teste da gestão

A T13 prepara o endereço **teste.brigaderia-amor-zeloso.pages.dev**. Ele usa o D1 **brigaderia-amor-zeloso-teste**. Pedidos, cobranças e alterações feitos nesse endereço ficam no banco de teste. A configuração usa o mesmo login do app.

A cópia contém informações privadas do banco de origem, como nomes e pedidos. Os telefones do cadastro são substituídos por números fictícios com DDD 00, não roteáveis, distintos para respeitar o cadastro. Sessões, inscrições e filas de avisos, comprovantes de backup, caches, registros de idempotência e a configuração Pix da empresa ficam fora da cópia. Nomes, endereços, valores e textos livres podem continuar sendo reais. Mantenha o ambiente restrito às pessoas já autorizadas.

## Preparar uma vez

1. Na Cloudflare, abra **Storage & databases → D1 → Create database**. Digite `brigaderia-amor-zeloso-teste`. Feito em 19/11: o ID `f377d813-1cf1-492f-b716-2010e3bd70c1` já está em `wrangler.jsonc` (`env.preview`).
2. No GitHub, abra **Settings → Environments → New environment**. Nomeie `ambiente-teste` e permita apenas a branch **main** em **Deployment branches and tags**. Adicione os segredos de ambiente `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` e `TEST_D1_DATABASE_ID`. Use a mesma conta e o mesmo token usados em `homologacao-d1`. Esse token precisa de **D1 Edit** na conta e dispensa permissão de Pages. Cadastre o ID do banco novo também em `TEST_D1_DATABASE_ID`. O segundo cadastro permite conferir o destino antes de qualquer gravação. Guarde o token no GitHub.
3. No Cloudflare Zero Trust, abra **Access controls → Applications** e edite a aplicação do app. Adicione `teste.brigaderia-amor-zeloso.pages.dev` e `*.brigaderia-amor-zeloso.pages.dev` na mesma aplicação, com a política de e-mails já aprovada. Preserve o hostname de produção. Assim o login usa o mesmo `ACCESS_AUD`.
4. No projeto **Pages → Settings → Bindings**, confira o ambiente **Preview**. Se houver um binding de painel, ele precisa apontar para o banco **brigaderia-amor-zeloso-teste**. Confira separadamente que **Production** ainda aponta para o seu banco atual. Nas prévias, não cadastre chaves VAPID. Remova ou restrinja prévias antigas publicadas com configuração anterior à T13, pois elas ainda podem usar o binding anterior.

## Atualizar e copiar

No GitHub abra **Actions → Ambiente de teste (manual) → Run workflow**, escolha a branch **main** e selecione a etapa abaixo. Marque **Autorizo esta ação no ambiente de teste** para ações que alteram o ambiente. Aguarde o resultado de cada etapa antes de executar a próxima.

| Modo                  | O que deve acontecer                                                                                                                                  | Se falhar                                                                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **ATUALIZAR_APP**     | Atualiza a branch `teste` com a `main` por avanço direto. O Pages conectado ao GitHub deve publicar o endereço fixo.                                  | Confira se a branch `teste` está habilitada nas prévias do Pages. Se o GitHub recusar o avanço, peça ao Claude para conferir a divergência. |
| **VERIFICAR**         | Mostra apenas números de migrações, linhas por tabela e violações. Pode mostrar zero tabelas na primeira execução.                                    | Confira se o ID de teste no GitHub bate com o ID do D1 novo e o do `wrangler.jsonc`.                                                        |
| **APLICAR_MIGRACOES** | Aplica as migrações só no teste. Esperado: zero pendentes e zero violações. Ainda precisa da cópia para ter cadastros e permissões de login.          | Rode **VERIFICAR** e peça revisão do resultado antes de seguir.                                                                             |
| **COPIAR_DO_REAL**    | Lê o banco de origem, substitui o conteúdo do teste, confirma contagens e vínculos e apaga os temporários. Esperado: zero pendentes e zero violações. | Rode **VERIFICAR**. Se a escrita no teste falhar, a prévia fica bloqueada até corrigir a causa.                                             |
| **LIMPAR**            | Apaga as tabelas do teste e reaplica as migrações. Ficam só metadados e padrões técnicos. Para voltar a usar a gestão, rode **COPIAR_DO_REAL**.       | Rode **VERIFICAR** e peça revisão.                                                                                                          |

**COPIAR_DO_REAL substitui os pedidos feitos no teste.** Faça essa etapa só com autorização, numa janela de baixa atividade: a exportação D1 pode tornar a origem temporariamente indisponível para consultas. A etapa lê a produção e grava apenas no teste. O workflow não publica dumps, logs de conteúdo ou artefatos de banco no repositório.

Depois, abra **https://teste.brigaderia-amor-zeloso.pages.dev/gestao** em janela anônima. Faça login e procure a faixa **AMBIENTE DE TESTE · dados não são reais** antes de criar um pedido. Abra **Mais → Preferências** para conferir que os avisos estão desativados. Antes de abrir um link do WhatsApp, o app pede uma confirmação adicional. Para ensaiar chamadas a mapas ou mensagens, use endereços e textos de demonstração. Se a faixa não aparecer, pare e confira o endereço e a configuração do Pages.
